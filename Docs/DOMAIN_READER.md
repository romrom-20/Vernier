## What the real runtime established

The adapter contains 72 finite learned tensors (2,113,536 values) across 36
query, attention-output and MLP-output modules in the last twelve blocks. A fused
copy changes only those modules: all other base tensors are bit-identical.
Non-text tensors are preserved, and the export supplies missing unused shared-KV
keys from their true owners. Loading successfully is separate from quality.
The original QAT GGUF and the MLX training base have different quantization and
runtime paths, so comparisons against the installed model are deployment
comparisons, not a pure measure of training's effect.

On the 36 existing coding goal regressions, the original model matched 29, the
trained export 26, stock Qwen 23 and neutral Qwen 21. A faithful readable-packet
trial on original Gemma matched 20. All use the actual read, same-model critic and
Swift validation path. These inspected examples are development/regression
material. None of these candidates qualified for a coding release.

The readable packet keeps the same bounded quotes, roles, witness IDs, current
anchor, source scope, origin and prior-hypothesis metadata. It changes their
presentation. It is guarded behind an isolated probe flag and disabled in the
normal app. The trial does not establish that clarity to a human improves a
small model's performance.

The profile comparison also found a task-scope issue: asking only about H while
expecting the assistant's A claim was ambiguous. A prospectively frozen second
variant explicitly scopes the whole excerpt, states choice/permission contrasts
and uses a typed schema. This combines prompt and decoding changes; it is not a
one-factor ablation. Its development results selected neutral Qwen for the
separate personal diagnostic. The original coding reader is retained. Test
results cannot reselect a model or prompt.

Attaching this LoRA directly to the original GGUF was considered but not run:
the installed [Ollama 0.40.9 create handler](https://github.com/ollama/ollama/blob/v0.40.9/server/create.go#L100)
rejects all adapter overlays. No live runtime downgrade was attempted.

## Reproduction and interpretation

Use a new ignored output directory for a new study. Generate the invented corpus
with `build-observer-domain-fixtures.py`; export its coding frames with the
isolated `--work-model-probe --export-work-packets-only` path; then run
`observer-domain-study.py prepare`, `train`, `collect-checkpoints`, development
`evaluate` and `select`. Record any prospective amendment before candidate output
review. Use offline Hugging Face settings and the recorded base hash. Do not
silently reinterpret a stopped run as complete.

`observer-domain-runtime.py` checks the explicit profile separately through
loopback Ollama. Pass `--scope whole-excerpt-2` to reproduce the final profile
method. Each saved reply includes prompt/schema hashes and completion state.
Coding goals additionally require `--work-model-probe`, not a proposal-only score.
The typed profile is evaluation-only; it has no live area summaries or source
connector. The A completion flag is supported by A, not by target witness H.
Per-actor source links would be required before integration.

All inspected fixtures become regression material. New tests must include fresh
mixed acts, scope changes and disagreements between speakers. A model agreeing
with its own critic does not independently establish an interpretation. The next
useful design is a source-linked record of choices, execution permission, attempts
and outcomes, supplied with an explicit assistant context, before prose about an
area. Neither this training nor the earlier direct edits establish general
reasoning or human feelings from weights.
